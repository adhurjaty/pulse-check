# Pulse Check

Live room-based polling for classroom discussions. Go backend (standard library only), plain HTML/JS frontend, Server-Sent Events for live updates.

## Run locally

```sh
HOST_PIN=dev go run .     # http://localhost:8080, state saved in ./data/state.json
go test -race ./...
```

Configuration comes from environment variables:

| Variable | Default | Meaning |
|---|---|---|
| `PORT` | `8080` | Port to listen on. |
| `DATA_DIR` | `./data` (`/data` in Docker) | Where `state.json` is saved. |
| `HOST_PIN` | none | Secret for host controls. If it isn't set, host routes are disabled. Use a long passphrase, since students can reach the API. |

State is saved to disk within half a second of any change, and again on shutdown. The file is replaced atomically. If it can't be parsed at startup, it's moved aside to `state.json.corrupt-<time>` and the server starts empty.

## Pages

- `/` is the student page. Students join by typing the room code, or open `/?r=CODE` directly (the QR code will link there). They answer each question, can change their answer until voting closes, and see the results on their phone. Their anonymous ID is stored in the browser, so a reload keeps their vote. If the connection drops, a "Reconnecting…" banner shows and the page catches up on its own.

The results bars use a diverging blue ↔ red scale: blue for the first half of the choices, red for the second, strongest at the ends. Every bar is labeled with its choice, count and percentage, so color is never the only cue.

## Question files

You upload a JSON question file when you create a room. `questions.schema.json` defines the format. If your file starts with `"$schema": "./questions.schema.json"`, editors with a JSON language server (such as `jsonls` in Neovim) autocomplete fields and flag mistakes as you type. See `sample-questions.json` for an example.

```json
{
  "title": "Engineering Ethics",
  "choices": ["Fine", "Fine with reservations", "Uncomfortable", "Unacceptable"],
  "questions": [
    { "text": "The question, shown large.", "detail": "Optional context, shown smaller." }
  ]
}
```

- `title` (required): up to 200 characters.
- `choices` (optional): 2 to 6 unique entries. Defaults to the four shown above.
- `questions` (required): 1 to 20 entries. `text` is required (up to 500 characters). `detail` is optional (up to 1,000 characters).

An invalid file is rejected with every problem listed at once, for example `questions[2]: unknown field "txt"`. Question numbers in these messages start at 0.

## API

Host routes need an `X-Host-Pin` header. Errors are JSON: `{"error": "..."}`.

| Route | Who | Purpose |
|---|---|---|
| `POST /api/host/check` | host | Check the PIN (204 if correct). |
| `POST /api/rooms` | host | Create a room. The body is a question file. Returns 201 with the room's snapshot, or 422 with `problems`. |
| `GET /api/rooms/{code}?voter=ID` | anyone | Current snapshot. |
| `GET /api/rooms/{code}/events?voter=ID` | anyone | Server-Sent Events: a snapshot on connect and after every change (bursts are merged), plus a `ping` event every 15 s so clients can detect a dead connection. |
| `POST /api/rooms/{code}/join` | anyone | `{"voter"}` |
| `POST /api/rooms/{code}/vote` | anyone | `{"voter", "question", "choice"}`. Returns 409 if that question isn't open. |
| `POST /api/rooms/{code}/control` | host | `{"action": "advance" or "back", "phase", "index"}`. `phase` and `index` are the room's current position. A repeated press is rejected with 409 instead of skipping ahead. |
| `GET /api/rooms/{code}/results.csv` | host | Counts for every question. |

Room codes are case-insensitive. Voter IDs are 1–64 characters of `[A-Za-z0-9_-]`, generated by the browser. Snapshots never include other voters' IDs or choices, and they have no per-choice counts while voting is open.

Also available: `GET /healthz`.
